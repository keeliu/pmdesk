# 实施任务

## 规格覆盖对照

| 能力 | 任务分组 | 覆盖场景 |
| --- | --- | --- |
| requirement-lifecycle | 1、9 | 14 阶段模型、流转门禁、里程碑联动、编号展示、存量迁移、工作台映射、发布联动 |
| requirement-profile | 1、2、3 | 档案字段、应用功能点、负责人、单条/批量/迭代范围进展维护、入口一致 |
| requirement-detail | 2、5 | 详情入口、聚合、基本信息、过程文档、进展、详情内维护、与工作台边界 |

| requirement-tracking | 1、2、9 | 状态机与批量更新、六个里程碑、试点节点、顺序校验、回填、逾期 |
| requirement-intake | 9 | 待澄清箱状态口径、合并与丢弃 |
| requirement-confirmation | 2、9 | 确认后待需求分析、驳回退回、入池筛选 |
| requirement-review | 2、9 | 需求评审中、多轮评审、待开发门禁、不通过退回 |
| release-planning | 3、9 | 发布门禁、待上线发版批量推进、失败回滚 |

| ai-orchestration | 4 | 技能包注册、环节映射、覆盖自检、补齐、说明书技能迁移 |
| access-control | 2、3、4、6、9 | 详情写入、批量进展、知识库只读、技能包补齐、阶段动作授权 |

## 0. 确认与准备

- [x] 0.1 用户确认本变更的提案、设计与增量规格，冻结范围
- [x] 0.2 记录当前场景测试、类型检查与生产构建基线
- [x] 0.3 确认现有开发服务器与数据卷可重建，准备迁移前备份

## 1. 数据模型与迁移

- [x] 1.1 需求表新增需求说明与负责人字段，历史记录保持为空
- [x] 1.2 里程碑模型新增试点完成时间，实际时间与计划时间均参与顺序校验；开发提测显示名调整为开发完成
- [x] 1.3 应用 JSON 读取归一化功能点数组，提供稳定功能点标识与同应用名称去重
- [x] 1.4 原型、需求说明书与迭代说明书新增更新时间，并在生成、修订、确认、发布时写入
- [x] 1.5 批次记录新增类型与变更内容字段，历史批次回填为状态批次
- [x] 1.6 迁移脚本幂等执行，重复启动不产生重复列或重复数据

## 2. 需求档案与进展接口

- [x] 2.1 实现需求档案保存：需求说明、负责人、应用与功能点，含应用范围校验、名称去重、审计与事件
- [x] 2.2 扩展里程碑接口：六个节点、计划与实际、顺序校验、变更历史与审计
- [x] 2.3 实现单条进展维护：里程碑、负责人与状态组合提交，任一冲突整体拒绝
- [x] 2.4 实现批量进展预览：按勾选或迭代范围计算目标集合、逐条门禁与字段校验
- [x] 2.5 实现批量进展执行：权限不足整批拒绝；门禁失败逐条跳过；统一生效时间；写批次与逐条审计
- [x] 2.6 迭代范围排除需求调研中与已丢弃需求；已发布迭代内需求逐条拒绝
- [x] 2.7 场景测试：档案读写、功能点重复与越界、负责人校验、单条冲突、批量全成功/部分失败/整批拒绝/迭代范围/已发布迭代

## 3. 需求详情聚合接口
