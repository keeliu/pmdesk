## MODIFIED Requirements

### Requirement: 需求清单浏览
系统 SHALL 提供需求清单界面，支持按项目、迭代、阶段状态、涉及应用与负责人浏览与筛选。

#### Scenario: 浏览清单
- **WHEN** 用户打开需求清单
- **THEN** 系统分页展示已分配编号且未丢弃的需求
- **AND** 每行显示编号、标题、阶段状态、迭代与负责人

#### Scenario: 查看需求详情
- **WHEN** 用户点击某条需求的编号或标题
- **THEN** 系统打开该需求的需求详情页
- **AND** 保留清单的筛选条件以便返回

#### Scenario: 打开工作台
- **WHEN** 用户点击需求清单中的「打开」
- **THEN** 系统按当前状态进入对应环节的需求分析工作台
- **AND** 不改变需求详情入口

#### Scenario: 按阶段筛选
- **WHEN** 用户按状态筛选需求清单
- **THEN** 系统按 0 至 13 阶段顺序展示全部可选阶段及非阶段状态
- **AND** 不提供已废弃的旧状态名称


### Requirement: 迭代说明书组装
系统 SHALL 按迭代聚合全部纳入需求的分析内容，使用项目登记且适用于「说明书」环节的技能，组装为迭代级需求分析说明书，并在生成时同时固化 HTML 与 Word 两份产物。

#### Scenario: 生成草稿版
- **WHEN** 产品经理在迭代详情发起生成说明书
- **THEN** 系统纳入迭代内状态不为需求调研中、已丢弃的需求
- **AND** 组装迭代总览、需求分篇与附录
- **AND** 缺失内容在对应章节标注待补

#### Scenario: 生成正式版
- **WHEN** 全部纳入需求均具备分析版本、一致性核查通过、原型已确认且说明书已发布
- **THEN** 系统生成正式版本并标注版本号与生成时间
- **AND** 每个章节标注来源需求编号、更新时间与阶段状态

#### Scenario: 正式版缺项
- **WHEN** 任一纳入需求缺少分析版本、未通过一致性核查、原型未确认或说明书未发布
- **THEN** 系统拒绝生成正式版
- **AND** 输出缺项清单并允许生成草稿版

#### Scenario: 需求内容更新
- **WHEN** 迭代内某条需求产生新的分析或说明书版本
- **THEN** 既有迭代说明书标记为待更新
- **AND** 不自动合并，须重新生成

#### Scenario: 迭代为空
- **WHEN** 迭代内没有可纳入的需求
- **THEN** 系统拒绝生成说明书
- **AND** 提示先完成需求排期与确认

#### Scenario: 使用技能生成
- **WHEN** 用户确认生成说明书并选择了一个可用文档技能
- **THEN** 系统按该技能的 HTML 模板与校验规则组装文档
- **AND** 版本记录技能绑定、技能 slug、技能版本与模板摘要
- **AND** 文档页脚与附录标注生成技能与版本

#### Scenario: 阶段范围
- **WHEN** 迭代内同时存在需求调研中、已丢弃与已排期需求
- **THEN** 系统只纳入已排期需求
- **AND** 在生成报告中列出未纳入需求与原因
