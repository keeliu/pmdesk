## Context

本项目从零建设，没有存量系统与数据。约束来自三方面：

1. **交付形态**：Qoder Sites 云端站点，前端、函数、数据库、对象存储由平台托管。
2. **能力来源**：分析、图表、原型等方法论沉淀在技能包中，云端无法直接调用本机技能目录，因此技能以"上传注册的包"形式执行。
3. **用户约束**：产品经理不接受学习新表单与流程，必须用自然语言完成操作；同时不能容忍 AI 随意改动事实。

## Goals / Non-Goals

**Goals**

- 一条需求可从待澄清箱走到开发状态，全链路产物一致、可追溯、可回放。
- 模型、技能、代码三层职责清晰，模型不越权。
- 分析与原型采用统一的"左会话、右只读预览"形态。
- 状态、编号、门禁、评分全部由代码保证确定性。

**Non-Goals**

- 不做代码生成与发布。
- 不做工时与资源排班。
- 不做多租户与计费。
- 不追求一次覆盖所有需求类型，首版按新功能与功能优化两类设计。

## Decisions

### 决策 1：待澄清箱与需求池分离，编号只在确认时分配

未确认需求没有编号，数据层编号字段允许为空。确认动作在一个事务内完成完整性校验、取号与状态流转，保证并发下不重号、不跳号。

**取舍**：未确认需求无法被外部系统引用；换来的是需求池里没有半成品，统计口径干净。

### 决策 2：分析右屏只读，修改只走会话

右屏不提供任何编辑控件，服务端拒绝非会话来源的分析写入。模型生成提案，右屏以差异高亮呈现，确认后落库。

**取舍**：牺牲了"直接改一行字"的便捷；换来的是每次修改都有指令、有来源、可回放，避免两个编辑入口导致版本分叉。

### 决策 3：环节是视图分组，不是状态

工作台五环节（澄清、分析、原型、评审、调整）只决定右屏展示什么、调用哪个技能；需求状态由状态机独立维护，通过门禁与环节关联。

**取舍**：用户需要理解"看了不等于做了"；换来的是状态机语义单一，不会被 UI 操作污染。

### 决策 4：技能以包形式注册

技能包 = 元信息 + 输入契约 + 提示词模板 + 输出 JSON Schema + 产物模板 + 校验规则。升级技能不改变产物结构。

**取舍**：需要维护技能版本与契约；换来的是可重复执行、可回归测试、可替换模型。

### 决策 5：模型只能在封闭动作清单内操作

动作清单由代码定义（创建需求、确认需求、更新分析、生成原型、发起评审、关闭建议、变更状态等），模型负责映射意图与填充参数，不得构造新动作。

**取舍**：灵活性受限；换来的是可测试、可审计、可拦截越权。

### 决策 6：说明书、分析、原型三版本互锁

说明书引用具体的分析版本与原型版本，任一变更生成新版本，旧版本可对比与回滚。改进建议关闭时必须关联到具体的说明书版本，差异为空则驳回。

**取舍**：存储与渲染成本上升；换来的是"已消除"不可造假。

### 决策 7：变更分级由规则计算，模型只做解释

涉及应用、集成点、验收口径三项任一变化，强制判定为重大变更。产品经理可上调等级，不可下调；下调需管理员豁免并留痕。

**取舍**：少数合理的小范围调整会被判重；换来的是范围不会被悄悄扩大。

### 决策 8：导出走服务端渲染

说明书导出 HTML 与 Word 均在服务端完成，HTML 自包含、不依赖 CDN，图片与原型截图内嵌。

**取舍**：服务端渲染资源占用高；换来的是导出结果稳定、可审计、离线可读。

## Architecture

```text
交互层   会话工作台 / 只读预览 / 项目与迭代视图
   ↓
编排层   意图路由 → 动作清单 → 状态机与门禁 → 技能调度 → 提案确认
   ↓
能力层   技能注册表 / 模型网关 / 确定性计算 / 文档与原型渲染
   ↓
数据层   需求库 / 产物与版本 / 事件日志 / 对象存储
```

## Risks / Trade-offs

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 模型输出不稳定 | 分析质量波动 | Schema 校验、重试一次、人工接管、全量留痕 |
| 右屏只读被绕过 | 版本分叉 | 服务端拒绝非会话写入；前端不提供入口 |
| 建议闭环流于形式 | 已消除但内容未变 | 关闭必须关联版本，差异为空驳回 |
| 变更分级误判 | 范围扩大 | 三项关键变化强制判重，只上调不下调 |
| AI 成本失控 | 预算超支 | 按环节设 token 预算、结果缓存、低价值调用改规则 |
| 技能迁移成本高 | 上线延期 | 先迁移澄清、分析、原型三个核心技能 |

## Migration Plan

全新项目，无数据迁移。上线顺序按 tasks.md 的五个阶段推进，每阶段交付可演示版本。
