## Why

产品经理的需求管理被拆散在聊天、会议纪要、文档、表格与设计工具之间，需求来源无法归集，分析口径不一致，评审结论不可追溯，原型验证周期长，状态与排期依赖人工同步。

现有 AI 工具能生成内容，但产出停留在对话中，既不可校验也不可流转，无法支撑"从需求到开发"的完整链路。

因此需要从零建设一个需求管理工作台：以自然语言为唯一操作入口，以技能包承载分析方法论，以代码保障状态、编号、门禁与权限的确定性。

## What Changes

- **新增**项目与迭代管理层：按项目画像四步建项，支持多项目切换；项目内可创建与切换迭代，查看全部迭代与全部需求。
- **新增**待澄清箱与需求池两段式管理：未确认需求不分配编号，确认后分配 `REQ-<项目号>-<流水号>` 并入池。
- **新增**澄清能力：缺口识别与选项化追问，初判需求涉及的应用并与项目系统范围比对，所有确认信息持久化。
- **新增**会话式需求分析：会话绑定需求后进入分析模式，右屏按"需求描述、业务流程说明、功能设计、集成说明"四段只读呈现，自动提示关联需求。
- **新增**原型工作台：由分析生成可交互原型，支持自然语言改稿，改稿同步更新原型 HTML 与说明书对应章节，确认后写入说明书。
- **新增**需求清单与需求分析说明书：清单可浏览与导出，说明书支持在线 HTML 预览与 Word 导出，均带版本。
- **新增**在线评审与改进建议闭环：在说明书与原型上批注，意见归并为建议，逐条闭环后需求方可进入开发。
- **新增**开发期变更分级：一般变更直接更新，中等变更知会确认，重大变更重新登记或重新评审。
- **新增**状态跟进与迭代规划：状态机、风险预警、我的待办、进展摘要、优先级评分、容量核算与依赖排期。
- **新增**AI 编排层：统一会话入口、封闭动作清单、提案确认闸门、模型网关、技能包注册与成本可观测。
- **新增**角色权限与审计：服务端权限校验，AI 以发起人身份执行，导出与分享留痕。

## Impact

### 新增能力

| 能力 | 说明 |
| --- | --- |
| project-iteration-management | 项目创建、画像、切换、成员；迭代创建、切换、容量 |
| requirement-intake | 多源登记、拆分、去重、待澄清箱 |
| requirement-clarification | 缺口追问、涉及应用初判、澄清记录留存 |
| requirement-confirmation | 确认清单、编号分配、确认快照、入池 |
| requirement-analysis | 会话绑定、四段分析、只读预览、关联需求、一致性校验 |
| prototype-workbench | 页面规划、原型生成、交互预览、改稿、写入说明书 |
| specification-publishing | 说明书组装、HTML 预览、Word 导出、需求清单浏览与导出、版本 |
| requirement-review | 在线评审、意见转建议、逐条闭环、开发门禁、评审档案 |
| change-control | 变更发起、影响评估、自动分级、重新评审或重新登记 |
| requirement-tracking | 状态机、事件时间线、风险预警、待办、摘要、通知 |
| release-planning | 优先级评分、容量管理、依赖图、排期与发布门禁 |
| ai-orchestration | 会话与动作清单、提案确认、模型网关、技能包、成本 |
| access-control | 角色权限、敏感动作限制、AI 身份、审计、分享 |

### 影响范围

- **代码**：全新代码库，无存量兼容与数据迁移。
- **数据**：新增工作空间、项目、需求、澄清记录、分析版本、说明书版本、原型、评审、改进建议、变更记录、迭代、事件、技能执行记录等实体。
- **外部依赖**：模型服务（OpenAI 兼容协议）、邮件通道。
- **不在本期**：代码托管与 CI/CD、工时与甘特、移动端 App、商业化计费、多租户。

### 交付形态

Qoder Sites 云端站点，单一 Web 工作台，桌面浏览器优先。

## Out of Scope

- 不直接写生产代码，只生成原型与需求产物。
- 不替代即时通讯，通知走站内与邮件。
- 不做资源精细排班与成本核算。
- 不做多组织 SaaS 与套餐计费。
