## Why

迭代需求分析说明书目前由固定模板直接拼装，与项目里已经登记、配置的「说明书组装」技能没有关系：模板改版要改代码，导入的技能包也无法参与文档产出。同时存在三处交付缺口：

1. **生成不经过技能**：分析、原型已经按技能执行，迭代说明书却直接调用渲染器，无法追溯本次文档使用了哪个技能与版本。
2. **Word 与 HTML 不同源**：Word 在下载时按当前库内数据临时拼装，与生成时固化的 HTML 可能不一致；历史版本重下时尤其容易漂移。
3. **预览不是打开 HTML 文件**：预览在弹窗 iframe 中渲染，无法新标签页打开、无法直接保存或转发 HTML，评审时受限。

因此需要把迭代说明书的生成改为按项目技能执行，生成时同时固化 Word 与 HTML 两份产物，并让预览直接打开 HTML。

## What Changes

- **新增**说明书环节：技能适用环节从五个扩展为六个，新增「说明书」环节，用于绑定文档组装类技能。
- **新增**内置说明书组装技能：新增内置技能 `spec-assemble`（名称「说明书组装」），按 prd-assemble 的交付契约提供单文件自包含 HTML 模板与文档校验规则；新项目自动绑定，存量项目启动时幂等补齐。
- **修改**迭代说明书生成：生成时必须解析出一个启用且适用于「说明书」环节的项目技能；生成弹窗展示候选技能并允许选择，请求携带所选技能；未选择时按上一版本技能、内置技能、唯一候选的顺序解析，仍无法确定则拒绝生成。
- **新增**技能模板契约：文档技能可用 `artifact.html` 提供 HTML 外壳模板，必须包含 `{{content}}` 占位符；系统按固定占位符注入文档标题、副标题、目录、正文与页脚；模板中的脚本与外部资源引用一律拒绝。
- **修改**生成产物：一次生成同时产出 HTML 与 Word 并固化，Word 写入服务端文件存储并记录大小与摘要；版本记录使用的技能、版本与模板摘要；任一产物生成失败则不创建版本。
- **修改**在线预览：迭代说明书预览改为在新标签页直接打开 HTML 文件，不再使用弹窗 iframe；预览响应使用内联展示、禁止缓存、禁止内联脚本与外部资源。
- **修改**重新生成：重新生成沿用同一套技能解析、模板校验与双产物固化逻辑，默认选中上一版本使用的技能；上一版本技能不可用时必须重新选择，不静默降级。
- **保持**：草稿版/正式版门禁、版本序列、待更新标记、权限与审计模型不变；Word/PDF/Markdown 等既有导出入口继续可用，但 Word 优先返回生成时固化的文件。

## Impact

### 影响能力

| 能力 | 改动类型 | 说明 |
| --- | --- | --- |
| ai-orchestration | 新增 + 修改 | 新增说明书环节与文档技能模板契约；说明书生成必须经由注册技能执行并记录技能版本 |
| specification-publishing | 修改 | 迭代说明书按技能组装，生成时固化 HTML 与 Word；预览改为直接打开 HTML 文件 |

### 影响范围

- **代码**：技能环节枚举与内置技能补齐；迭代说明书生成改为技能解析 + 模板渲染 + 双产物固化；预览与 Word 接口调整；迭代详情生成弹窗与版本列表调整。
- **数据**：`iteration_specs` 增加技能标识、技能版本、模板摘要与 Word 文件记录；新增内置技能定义与项目绑定；不修改既有需求、分析、原型与评审数据。
- **兼容**：历史迭代说明书保留可预览、可导出；缺技能记录与 Word 文件的历史版本按内置技能回退生成 Word，不回写历史版本记录；不改变既有接口路径。
- **不在本期**：单需求说明书切换为技能驱动、技能在线编辑、技能市场、文档在线协同编辑、PDF 引擎替换。

## Out of Scope

- 不改变草稿版与正式版的门禁条件、迭代说明书版本序列与「待更新」标记规则。
- 不改变需求分析、原型、评审与状态机；文档技能只参与最终组装，不生成或改写分析内容。
- 不执行技能包内的脚本；文档模板只做占位符替换与安全校验。
- 不为自定义模板单独生成同结构 Word；Word 始终按系统标准章节结构生成，模板只影响 HTML 外观。
- 不在本期改造单需求说明书的生成与预览入口。
