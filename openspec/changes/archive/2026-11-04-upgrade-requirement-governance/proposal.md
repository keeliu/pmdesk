## Why

首版工作台已打通收集、确认、分析、原型、评审、变更与排期链路，但在实际使用中暴露出四类缺口：

1. **需求归属不清**：澄清阶段只收敛角色、目标、范围等六个维度，未强制记录提出企业、部门与提出人及其级别/岗位，导致优先级判断缺依据、责任追溯困难；优先级只有单一 RICE 分数，无法表达"极高/高/中/低"的业务口径，也无法解释为什么高。
2. **分析初稿形似而神不似**：点击"生成分析初稿"后，业务流程只给出概括性描述，功能设计与需求标题重复，没有按 prd-analysis 技能契约输出流程节点、角色、分支、功能架构、验收要点，分析结果无法直接进入评审。
3. **迭代缺少交付视角**：迭代只能排期，无法查看迭代内全部需求的全貌，也不能按迭代整合出一份可供评审与开发交底的需求分析说明书。
4. **状态跟进效率低**：状态只能逐条推进，无法按迭代批量更新，也不能用会话方式批量处理；状态变更缺少统一生效时间与里程碑时间口径。

因此需要在不改变既有状态机、门禁与权限模型的前提下，补齐提出方信息、优先级分级、技能化分析初稿、迭代详情与迭代级说明书、批量与会话式状态管理。

## What Changes

- **新增**提出方信息采集：企业、部门、提出人姓名、级别/岗位，企业取自项目画像的企业范围，缺失时阻断确认。
- **修改**澄清缺口识别与完成判定：在六个维度之外增加提出方信息，并纳入确认前置校验。
- **修改**确认清单与快照：确认时校验提出方信息与优先级建议值，快照固化提出方、优先级依据与里程碑初始状态。
- **修改**优先级评分：改为 P0-极高、P1-高、P2-中、P3-低 四级；按提出人级别/岗位、流程闭环必要性、影响广度、业务增量、效率提升、成本降低与投入产出比自动识别，展示逐项依据，人工覆盖须填写理由。
- **新增**分析初稿技能门禁：生成初稿必须调用 prd-analysis 技能契约，输出必须通过 schema 与质量规则校验；泛化描述、标题复述与占位内容不得生成提案，并给出缺失输入清单。
- **新增**需求里程碑：产品经理、评审完成时间、开发提测时间、完成测试验证时间、完成 UAT 时间、上线推广时间，支持按阶段自动回填、人工修正与逾期预警。
- **新增**批量状态更新：按迭代或筛选结果批量推进，逐条校验门禁，支持统一生效时间，返回成功与失败清单。
- **新增**会话式状态管理：跟进页右侧会话窗口按专题解析状态诉求，生成批量提案，确认后统一执行。
- **新增**迭代详情：汇总迭代目标、容量、全部关联需求、状态分布、里程碑与产物覆盖，提供批量更新与说明书入口。
- **新增**迭代级需求分析说明书：聚合迭代内全部需求，按 prd-pipeline 约定的自包含 HTML 契约在线预览，并支持 Word/PDF 导出与版本管理。
- **修改**敏感动作与审计：批量状态更新、迭代说明书生成与导出纳入敏感动作，逐条留痕并记录批次号。
- **修改**AI 动作清单：新增状态查询、批量状态更新提案、迭代进展查询与迭代说明书生成提案。

## Impact

### 影响能力

| 能力 | 改动类型 | 说明 |
| --- | --- | --- |
| requirement-clarification | 修改 + 新增 | 提出方信息采集，缺口识别与完成判定纳入提出方 |
| requirement-confirmation | 修改 | 确认清单、确认快照包含提出方与优先级依据 |
| release-planning | 修改 + 新增 | P0–P3 四级优先级、自动识别规则与依据展示 |
| requirement-analysis | 修改 + 新增 | 四段结构与功能设计的质量要求，分析初稿技能门禁 |
| requirement-tracking | 新增 + 修改 | 需求里程碑、批量状态更新、会话式状态管理、事件生效时间 |
| project-iteration-management | 新增 | 迭代详情视图 |
| specification-publishing | 新增 + 修改 | 迭代级说明书组装、HTML 在线预览、Word/PDF 导出、版本引用 |
| ai-orchestration | 修改 + 新增 | 技能契约执行、规划与跟踪会话动作 |
| access-control | 修改 | 批量动作与迭代说明书相关敏感动作留痕 |

### 影响范围

- **代码**：需求模型新增提出方、优先级维度、里程碑与生效时间字段；分析生成改为技能驱动并加质量门禁；迭代详情与迭代说明书新增页面与接口；跟进页新增批量操作与右侧会话。
- **数据**：需求表扩展提出方与里程碑；优先级 JSON 扩展维度与分级；新增迭代说明书版本与导出记录；事件表增加生效时间与批次号。
- **兼容**：存量需求按空值处理并在界面标记"待补"，不追溯失败；存量优先级保留原分值，首次编辑时按新模型重算。
- **不在本期**：跨迭代合并说明书、PDF 排版模板自定义、按企业拆分的多版本说明书。

## Out of Scope

- 不改变既有状态机的合法迁移集合与门禁条件。
- 不引入外部文档服务，HTML、Word、PDF 均在本地或服务端生成。
- 不内置任何企业、部门清单，全部由项目画像与用户输入提供。
- 不做工时核算、甘特图与资源精细排班。
