# 设计说明

## 1. 提出方信息模型

| 字段 | 来源 | 必填 | 说明 |
| --- | --- | --- | --- |
| 企业 | 项目画像 `enterprise_scope` | 是 | 统建单位或个性化单位枚举；画像外企业按"外部提出方"登记，须产品经理确认 |
| 部门 | 用户输入 | 是 | 自由文本，保留原文；不内置组织树 |
| 提出人姓名 | 用户输入或登记账号 | 是 | 外部表单提交时取提交人 |
| 级别/岗位 | 用户选择 + 文本 | 是 | 级别枚举：高层、中层、基层、外部；岗位为自由文本 |
| 联系方式 | 用户输入 | 否 | 仅用于澄清联系，不进导出正文 |

- 提出方信息在澄清阶段采集，AI 可从材料中提取候选值，但必须由用户确认后写入。
- 企业不在画像范围内时，不自动扩展画像；阻断确认并提示"更新项目范围"或"标记为外部提出方"。
- 对外表单只要求提交人与联系方式，企业、部门与级别在澄清阶段补齐，未补齐前不能确认。

## 2. 优先级模型

### 2.1 等级口径

| 等级 | 标签 | 判定口径 |
| --- | --- | --- |
| P0 | 极高 | 阻断关键业务流程闭环，或涉及合规、资金、安全底线，或全部单位/全部用户受影响且无替代路径 |
| P1 | 高 | 多单位或多角色核心流程增强，业务增量、效率或成本收益明确 |
| P2 | 中 | 单单位、单角色体验优化，存在人工替代路径 |
| P3 | 低 | 低频、远期或投入产出比明显偏低 |

### 2.2 自动识别分值

总分 100，由确定性规则计算，AI 只负责从材料中提取信号与证据。

| 维度 | 权重 | 取值 |
| --- | --- | --- |
| 流程闭环必要性 | 30 | 缺失则流程无法闭环 30；需人工绕行 15；增强项 0 |
| 影响广度 | 20 | 全部单位/全部用户 20；多单位/多角色 14；单单位 8；单岗位 3 |
| 提出人级别/岗位 | 15 | 高层/关键岗位 15；中层/业务负责人 10；基层 5；外部 3 |
| 业务增量 | 15 | 直接收入、合规或风险控制 15；明显提升 10；一般 5 |
| 效率提升 | 10 | 显著 10；一般 5；不可量化 0 |
| 成本降低 | 10 | 显著 10；一般 5；不可量化 0 |
| 投入产出比 | 校正 | 高产出低投入 +10；低产出高投入 -10；其余 0 |

- 阈值：`≥75` 为 P0，`55–74` 为 P1，`35–54` 为 P2，`<35` 为 P3。
- 底线规则：命中合规、资金、安全或无替代路径的流程阻断时，等级不低于 P0；该判定必须给出依据。
- 提出人级别最高只贡献 15 分，不得单独把需求抬到 P0 或 P1。
- 同分时依次比较流程闭环必要性、影响广度、业务增量。
- 人工覆盖保留系统建议值、覆盖理由与操作人；覆盖不改变历史评分记录。

### 2.3 AI 与规则的职责边界

- AI 负责：从澄清记录、原始材料与提出方信息中提取维度信号，输出带证据的候选取值。
- 规则引擎负责：按权重计算总分与等级，保证同一输入得到同一结果。
- 两者不一致时以规则结果为准，AI 的候选取值作为依据展示。

## 3. 分析初稿的技能化

### 3.1 执行契约

- 生成入口固定调用 `prd-analysis` 技能，不拼接自由提示词。
- 输入：确认快照、提出方信息、项目画像与系统范围、澄清记录、上下文资料、关联需求、历史同类分析、需求模板。
- 输出：四段结构 JSON，字段与 `04-analysis.json` 契约一致，另附每段的证据引用。

### 3.2 质量门禁

在 schema 校验之后追加质量规则，任一不通过即不得生成提案：

| 检查 | 规则 |
| --- | --- |
| 业务流程 | 至少 3 个节点，包含节点、角色、动作、分支、结果、下一步；存在异常分支或明确说明单步流程理由 |
| 功能架构 | 至少 1 个模块、2 个功能，功能名为动宾结构，不得与需求标题完全相同 |
| 功能说明 | 每条含触发场景、处理规则、结果、优先级与可观察的验收要点 |
| 辅助支撑 | 涉及权限、通知、配置、日志时必须有对应支撑功能 |
| 集成说明 | 每个集成点含应用、方向、数据对象、触发时机；应用必须在系统范围或登记为外部依赖 |
| 反占位 | 不得出现"处理相关业务""详见后续""待补充"等占位表述作为唯一内容 |

### 3.3 失败处理

1. 首次失败：返回缺失输入清单，指出需要补充的澄清项或资料。
2. 自动重试一次，仍失败则输出结构化骨架，逐段标注"待补充"与原因。
3. 骨架不得创建分析版本，也不得进入原型环节；用户补齐输入后可重新生成。
4. 模型不可用时降级为规则引擎生成的骨架，并在界面明示原因，不伪装为完整分析。

## 4. 需求里程碑

| 字段 | 自动回填时机 | 说明 |
| --- | --- | --- |
| 产品经理 | 确认入池 | 取当前确认人，可转交 |
| 评审完成时间 | 评审结论为通过 | 多轮评审取最后一次通过时间 |
| 开发提测时间 | 进入待验收 | 可人工修正 |
| 完成测试验证时间 | 待验收中登记测试通过 | 由测试负责人登记 |
| 完成 UAT 时间 | 待验收中登记 UAT 通过 | 由业务方或产品经理登记 |
| 上线推广时间 | 进入已上线 | 可人工修正 |

- 时间顺序校验：评审完成 ≤ 提测 ≤ 测试验证 ≤ UAT ≤ 上线推广；违反时拒绝写入并指出冲突字段。
- 未发生的里程碑保持为空，不写预估日期。
- 计划日期与实际日期分开存储；实际日期超过计划日期时生成逾期预警。
- 进入待验收要求提测时间已填；进入已上线要求测试验证与 UAT 时间已填。

## 5. 批量与会话式状态更新

- 批量更新按筛选结果或迭代确定范围，逐条校验状态机与门禁，不绕过任何条件。
- 支持统一生效时间：不晚于当前时间，且不早于该需求进入当前状态的时间；未指定时使用服务器时间。
- 事件同时记录生效时间与实际写入时间，补录生效时间标记为补录。
- 部分失败不回滚已成功项，返回成功清单与失败原因；失败项状态保持不变。
- 会话窗口绑定当前项目或迭代，解析意图后生成提案，提案展示逐条前后状态、生效时间与门禁失败项；确认后才执行。
- 会话只能查询与提案，不能直接写状态；权限按发起人校验，AI 不具备额外权限。

## 6. 迭代详情

- 入口：迭代列表行、顶部迭代选择器、规划页。
- 内容：迭代名称、目标、起止日期、容量与占用、状态；需求按状态分组并显示数量；里程碑汇总与最近到期项；依赖与阻塞；分析、原型、说明书覆盖率。
- 操作：批量更新状态、生成迭代说明书、查看已发布说明书、移出需求；已发布迭代只读，禁止状态回退与新增排期。
- 空态：无需求时显示引导去规划页排期。

## 7. 迭代级说明书

### 7.1 内容结构

1. 迭代总览：目标、范围、起止时间、容量、状态分布、里程碑。
2. 需求分篇：每条需求按"需求描述、业务流程说明、功能设计、集成说明、验收口径"组织，复用单需求说明书内容与锚点。
3. 附录：需求清单与追踪矩阵、里程碑、风险与阻塞、待确认事项、一致性核查结果。

### 7.2 HTML 契约

沿用 prd-pipeline 的 prd-assemble 交付契约：

- 单文件自包含 HTML，图片与原型截图 base64 内嵌，不引用 CDN、外链样式或外部图床。
- 左侧目录树可跳转到迭代章节与每条需求，正文标题带稳定锚点。
- 五章正文与附录编号、图注、表题连续；缺图显示占位与原始说明。
- 支持窄屏阅读与浏览器打印，打印样式隐藏导航。

### 7.3 版本与门禁

- 草稿版：迭代内任意需求只要有分析内容即可生成，缺项在对应章节与附录中标注。
- 正式版：迭代内全部纳入需求均具备分析版本且一致性核查通过、原型已确认、说明书已发布；否则拒绝并输出缺项清单。
- 纳入范围：迭代内状态不为"已丢弃""待澄清"的需求；已关闭需求保留但标注归档。
- 单需求分析更新后，迭代说明书标记为"待更新"，不自动合并。

### 7.4 导出

- Word 与 PDF 由同一份 source 生成，章节数、图表数、需求条目数与 HTML 一致。
- PDF 通过无头浏览器打印 HTML 生成；引擎不可用时导出失败并返回原因，不生成降级文件。
- 文件名含迭代名称与版本号；导出记录操作人、格式、范围与时间。

## 8. 权限与审计

- 批量状态更新要求对每条目标需求具备状态推进权限，任一条无权限则整批拒绝。
- 迭代说明书生成要求产品经理或管理员；导出对所有项目成员开放，访客仅可查看已发布版本。
- 批量操作写入批次号，每条需求生成独立事件与审计记录；批次记录汇总成功与失败数量。
- 会话提案的确认人即实际操作人，审计记录同时标注提案来源。

## 9. 备选方案与取舍

| 决策 | 备选 | 取舍 |
| --- | --- | --- |
| 优先级规则引擎 | 纯 AI 打分 | 选规则引擎，保证可复现与可解释；AI 只提取信号 |
| 分析初稿技能化 | 继续自由提示词 | 选技能契约，避免输出漂移；代价是需要维护技能版本与 schema |
| 迭代说明书复用单需求 HTML | 另建排版模板 | 选复用，保证同一套契约与验收；代价是迭代总览需新增章节映射 |
| PDF 无头打印 | 引入第三方转换服务 | 选无头打印，离线可用；引擎缺失时明确失败 |
| 批量更新部分成功 | 全量事务回滚 | 选部分成功并返回失败清单，符合排期批量操作习惯 |

## 10. 风险与未决问题

- **Q-101**：优先级权重与阈值需要按实际项目校准，当前取值为初始口径，首个迭代结束后复盘调整。
- **Q-102**：外部提出方的企业如何归一（自由文本还是画像扩展）尚未定；当前按"外部提出方"标记，不进入企业范围统计。
- **Q-103**：PDF 依赖运行环境的无头浏览器；部署环境未安装时只能导出 HTML 与 Word。
- **Q-104**：迭代说明书是否纳入已关闭需求按版本归档，待评审确认；当前保留并标注归档。
