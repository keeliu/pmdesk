# 设计说明

## 1. 规划入口归属

### 1.1 导航与路由

| 项 | 现状 | 调整后 |
| --- | --- | --- |
| 顶部导航 | 同时存在「迭代」「规划」 | 只保留「迭代」 |
| 规划地址 | `#/p/<项目>/planning` | 保持不变，历史链接继续可用 |
| 导航高亮 | 按当前 section 精确匹配 | 打开规划页时「迭代」保持高亮 |
| 进入规划 | 迭代页「去排期」、迭代详情「去规划 / 去排期」 | 统一为「规划」 |
| 返回路径 | 无固定返回入口 | 规划页提供「返回迭代」，回到迭代列表 |

- 规划页仍由迭代列表和迭代详情承载入口，不再出现在顶部导航。
- 迭代卡片上的入口文案、空态引导、详情页按钮和规划页标题统一使用「规划」；「排期」只保留在描述拖拽动作的辅助文案中，不作为入口名称。
- 规划页的优先级计算、容量校验、拖拽排期、发布门禁与接口全部不变，仅调整入口归属与文案。

### 1.2 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 把规划看板整体并入迭代列表页 | 未采用 | 需要重写拖拽与容量视图，收益低于改造成本 |
| 保留规划页签，仅重命名 | 未采用 | 与「不需要单独规划页签」的诉求不符 |
| 规划页作为迭代子路由，保留原地址 | 采用 | 改动小、深链兼容、不破坏现有测试 |

## 2. 项目技能模型

### 2.1 数据模型

新增项目技能绑定表，技能包定义仍存放在现有技能表：

```text
project_skills
  id                 TEXT PRIMARY KEY
  project_id         TEXT NOT NULL
  skill_id           TEXT NOT NULL          -- 指向技能包
  source_type        TEXT NOT NULL          -- builtin | import | reference
  source_project_id  TEXT                   -- 引用时为来源项目
  stages_json        TEXT NOT NULL DEFAULT '[]'
  enabled            INTEGER NOT NULL DEFAULT 1
  created_by         TEXT NOT NULL
  created_at         TEXT NOT NULL
  UNIQUE(project_id, skill_id)
```

- `stages_json` 取值只能是 `clarify / analysis / prototype / review / change` 的子集，空数组表示「由大模型识别」。
- 同一项目内同一技能 slug 只允许一个绑定：导入或引用同 slug 时返回冲突，要求先移除既有绑定。本期不做版本升级。
- 实际可用状态 = 绑定启用 **且** 技能包启用；任一为停用，执行入口不可用。
- 新项目创建时自动绑定内置技能；存量项目在启动迁移时幂等补齐，只补缺失项。
- 内置技能绑定不可移除，只能停用或调整适用环节；导入与引用技能可移除。

### 2.2 技能包契约

压缩包或文件夹根目录必须包含 `skill.json`（允许外层只有一层同名目录）：

```json
{
  "slug": "技能标识",
  "name": "技能名称",
  "version": "1.0.0",
  "description": "技能用途与适用场景",
  "stages": ["analysis"],
  "inputSchema": {},
  "outputSchema": {},
  "promptTemplate": "",
  "artifactTemplate": "",
  "validation": {}
}
```

- `slug`、`name`、`version` 必填；`stages` 可省略，省略等价于空数组。
- 可选文件按约定读取：`prompt.md`、`artifact.html`、`input.schema.json`、`output.schema.json`、`validation.json`；清单中的同名字段优先。
- 包内只读取上述声明性内容，不执行任何脚本或可执行文件。

### 2.3 导入校验与安全

| 检查 | 处理 |
| --- | --- |
| 压缩包格式 | 仅接受 zip；文件夹模式按浏览器提供的相对路径还原结构 |
| 路径安全 | 拒绝绝对路径、`..`、盘符路径与符号链接条目，防止目录穿越 |
| 文件数量与体积 | 单包不超过 200 个文件、解压后不超过 20 MB；超限直接拒绝 |
| 类型白名单 | 只保留清单、Markdown、HTML、JSON、纯文本；`.exe/.dll/.bat/.cmd/.ps1/.sh/.js/.mjs/.cjs/.py` 等可执行或脚本文件拒绝导入 |
| 清单校验 | `skill.json` 必须可解析且必填字段齐全；`slug` 只允许字母、数字、连字符与下划线 |
| 环节取值 | 只接受五个固定环节，未知值拒绝 |
| 冲突 | 当前项目已存在同 slug 绑定，返回冲突并提示先移除 |
| 原子性 | 任一校验失败不写入技能包与绑定，不产生半成品 |

### 2.4 两种添加方式

1. **导入到当前项目**：上传 zip 或选择文件夹 → 服务端解析清单 → 建立技能包（若同 slug+version 的包已存在则复用）→ 建立 `source_type=import` 的绑定。来源项目记为当前项目。
2. **引用其它项目**：候选列表只包含「当前用户是成员的项目」中已启用、且来源为导入或引用的技能；引用后建立 `source_type=reference` 绑定，记录来源项目与技能包，但不复制技能包内容。

引用约束：

- 引用人必须对目标项目具备技能管理权限，且是来源项目成员；候选接口与服务端引用接口都按此过滤，未授权时不返回候选、不泄露技能内容。
- 内置技能不进入引用候选，因为每个项目已自动拥有。
- 来源项目停用技能包或移除绑定时，引用方绑定保留但标记「来源不可用」，执行时返回明确原因；本期不做自动解绑。
- 来源技能升版不自动同步；引用固定到引用时的技能包记录。

### 2.5 适用环节与执行

| 场景 | 行为 |
| --- | --- |
| 配置了环节 | 技能只在这些环节出现在可用列表；其它环节手动执行返回拒绝 |
| 未配置环节 | 技能在所有环节可见，由大模型根据技能说明、需求内容与当前上下文判断是否使用 |
| 会话自动使用 | 系统只向模型暴露当前环节可用技能；模型使用技能时必须在回复中说明技能与理由 |
| 手动执行 | 服务端按当前环节校验，不匹配时拒绝；执行结果不直接写库 |
| 模型不可用 | 不自动执行技能；界面明示技能未执行及原因，不伪装成功 |

执行记录写入现有调用记录表，字段包含技能 slug、版本、环节、触发方式（会话自动 / 手动）与结果状态。技能使用不绕过既有提案闸门：任何写回仍由原动作生成提案并经确认后生效。

### 2.6 接口契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/projects/:projectId/skills` | 当前项目技能列表，含来源类型、来源项目名、适用环节、启用状态 |
| GET | `/api/projects/:projectId/skills/reference-candidates` | 可引用的其它项目技能，按来源项目分组 |
| POST | `/api/projects/:projectId/skills/import` | 压缩包或文件夹导入，返回绑定与技能摘要 |
| POST | `/api/projects/:projectId/skills/reference` | 引用技能，提交技能包标识与适用环节 |
| PATCH | `/api/projects/:projectId/skills/:bindingId` | 调整适用环节或启停 |
| DELETE | `/api/projects/:projectId/skills/:bindingId` | 移除绑定；内置技能拒绝 |
| POST | `/api/requirements/:id/skills/:bindingId/run` | 在指定环节手动执行，服务端校验环节与可用状态 |

- 列表默认不返回提示词模板与产物模板，避免无关项目成员读取实现细节；执行在服务端完成。
- 现有全局技能接口不再作为项目技能入口；场景测试改为按项目断言。

### 2.7 审计

- 新增敏感动作：`skill.import`、`skill.reference`、`skill.config`、`skill.toggle`、`skill.remove`。
- 记录项目、技能标识、来源类型、来源项目、环节变化前后值、操作人与时间。
- 引用动作额外记录来源项目与被引用项目，便于来源方追溯；不记录提示词正文。

### 2.8 界面

- 设置页页签名称改为「技能管理」，卡片标题为「项目技能」，说明改为「技能只生成提案，不直接写库；按当前项目生效」。
- 主按钮改为「＋ 添加技能」，弹窗确认按钮改为「添加」；弹窗提供两个模式：
  - **上传技能包**：拖入 zip 或选择文件夹；解析成功后展示技能名称、版本、来源与可编辑的适用环节。
  - **引用其它项目**：先选来源项目，再选技能；展示来源项目名与技能说明，可编辑适用环节。
- 适用环节为五个复选项；不勾选时显示提示「不选择则由大模型在会话中按内容识别使用环节」。
- 列表行展示来源标签（内置 / 导入 / 引用·来源项目）、环节标签（或「自动识别」）与启停按钮；导入与引用技能提供「配置」「移除」，内置技能只提供「配置」「停用」。
- 非管理角色只读查看，不显示添加、配置、移除与启停入口。

## 3. 需求描述固定区

### 3.1 位置与结构

- 工作台右屏在预览区顶部新增固定区，和预览标题一起固定在滚动容器顶部：

```text
.wb-preview（滚动容器）
  .preview-sticky（sticky top: 0）
    .preview-head（环节标题 / 只读标识 / 刷新）
    .preview-brief（需求描述，最多三行）
  .preview-body（滚动内容）
```

- 只在分析、原型、评审、变更四个环节显示；澄清环节不显示。
- 固定区不参与预览内容的滚动，滚动时始终可见；小屏单列布局同样保持固定。

### 3.2 内容来源

按以下顺序取第一个非空内容：

1. 已确认需求的确认快照中的原文摘要；
2. 需求来源记录的原文摘要；
3. 需求来源记录的完整原文；
4. 澄清结论中的「目标与价值」「范围」「边界」按标签拼接；
5. 以上均为空时显示「暂无需求描述，可在澄清环节补充」。

- 固定区不新增需求字段，不改变确认快照结构。
- 展开详情时同时展示可用的元信息：来源文件名、提出方、涉及应用、确认时间与确认人；缺失项不显示。

### 3.3 截断与展开

- 正文最多三行，超出部分省略。
- 组件渲染后比较文本区 `scrollHeight` 与 `clientHeight` 判断是否溢出；溢出时显示「查看详情」。
- 文本、环节或窗口尺寸变化时重新判断，避免误显示或漏显示。
- 点击「查看详情」打开只读弹窗，完整展示描述并保留换行；弹窗内不提供编辑入口，修改仍通过左侧会话进行。
- 文案超过三行但无法测量时，以字符长度阈值作为兜底，保证入口可见。

### 3.4 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 把描述固定在左侧会话顶部 | 未采用 | 澄清后的分析内容在右侧滚动，固定在右侧才与阅读对象同屏 |
| 固定完整描述并允许折叠 | 未采用 | 完整描述占用过多高度，三行加详情入口更轻 |
| 只固定分析环节 | 未采用 | 原型、评审与变更同样需要对照原始诉求，行为应一致 |

## 4. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 固定区挤压预览空间 | 限制三行、压缩内边距；标题与描述同处一个吸顶容器，避免重复占位 |
| 压缩包目录穿越或压缩炸弹 | 路径校验、文件数/体积上限、类型白名单、解压后大小复核 |
| 跨项目引用泄露来源项目数据 | 候选与引用都校验双项目成员关系；列表只返回技能摘要与来源项目名；审计留痕 |
| 模型自动选择技能不稳定 | 只暴露当前环节可用技能；要求说明理由；执行记录可追溯；写回仍过提案闸门 |
| 存量测试依赖全局技能接口 | 同步改造场景测试，改为按项目断言，并保留内置技能作为默认数据 |
| 迁移产生重复绑定 | 迁移按项目与技能幂等插入，唯一约束兜底 |

## 5. 兼容与迁移

- 规划页地址不变；移除的只是导航入口，不影响已有深链与浏览器历史。
- 技能包定义表保持兼容；新增绑定表后，存量项目在启动时补齐内置技能绑定。
- 技能启停从全局改为项目绑定维度；技能包自身停用仍作为总开关，二者取与。
- 需求描述固定区只读取现有详情接口数据，不新增接口与字段，存量需求无需回填。
